## 1 要解决的问题

人在编辑器里改代码，编程 Agent 同时改同一批文件。Agent 依据的是它一段时间前读到的内容：

- 它按旧内容整份重写一个文件（Write），人刚改的行被写回旧的样子；
- 它想"从干净的状态开始"，执行 `git checkout -- 文件`、`git stash`、`git reset --hard`，人没提交的修改全没了；
- 它跑格式化工具、跨文件替换，把人刚改的行也改了；
- 它重新读了文件、看到了人的修改，仍然按自己的计划把那一行改回去。

Claude Code 自己已经有一些保护：Edit 是字符串替换，`old_string` 必须和文件现在的内容一样才能改；文件读过之后被改了，`old_string` 对不上就要重新读。但它不管 Bash 里的命令，不管"看到了也照样改"，Write 在新模型上也不一定要求重新读。也没有人优先的规则：人改过的行，Agent 读过之后照样可以改。

和 Blender 一样，目标是：**人改过的，Agent 不能改；由运行时强制执行，不靠提示词；不改 Claude Code，不改编辑器。**

人选定的做法（2026-11-01）：先接 Claude Code；按行算；Agent 的一次编辑碰到人的行就整次拒绝；只看存盘的内容。

## 2 账本：按行

### 2.1 单位

代码的单位是行，不认识任何语言（P4）：文件就是一行一行的字节，比较时不看行尾的换行符（CRLF 和 LF 算一样）。二进制文件、超过 2 MB 的文件整个文件算一行；超过 50 MB 的不管。

每个文件在账本里记着：

- 每一行的**标记**：最后改出这一行的那次修改（谁改的、在这个文件的第几版）。没记过的行是基线，没有作者。
- **删除点**：有人删掉了几行，留在两行之间的一个位置（记下删了几行、删掉的前几行）。整个文件被删掉，是文件开头的一个删除点（文件的墓碑）。

一次修改 = 账本里的旧内容到新内容的差异（`difflib`，先去掉相同的开头和结尾）。没变的行带着原来的标记，新写出来的行带上这次修改的标记，删掉的地方留删除点。行号变了，标记跟着行走。

### 2.2 谁改的

每次 hook 运行（Claude Code 调用工具前后、人发消息、会话开始），先看磁盘和账本哪里不一样：

- Agent 的一次编辑（Edit、Write）、一条命令（Bash）期间的变化，按第 3 节结算；
- 其余的都是**人**的（两次 Agent 执行之间磁盘上的变化）；
- 人做的 git 操作：HEAD 变了、文件变成了新的 HEAD 里的样子，记为 **git**（切分支、拉取带来的，不是人手改的）；
- 说不准的（执行期间别的东西也在改；命令没等到结束通知），记为**来源不明**。

只看存盘的内容：没按 Ctrl+S、也没开自动保存的修改，RightOfWay 看不到（编辑器在存盘时会发现文件被改过，提示比较或覆盖）。开自动保存（VS Code：`"files.autoSave": "afterDelay"`）就都能看到。

### 2.3 规则

Agent 一次修改的差异，碰到了下面这些，就是碰到了不能动的行：

1. 人改的、来源不明的行，还没交还、也还没提交的（R1）。对所有 Agent 都一样，看没看过都一样。
2. 别的 Agent、git 操作在这个 Agent 上次读这个文件之后才改的行（R3：按旧印象写的不生效）。它重新读过之后就可以改。
3. RightOfWay 自己的配置（`.claude/settings.json`、`.claude/settings.local.json`）：只有人能改。

"碰到"指改写、删掉了这些行，或者在受保护的删除点写东西（在人删掉的地方写回去，包括在两端）。紧挨着人的行插入、修改别的行，不算碰到：人改的那几行一个字都没变。

规则只在 `rightofway/code/ledger.py` 一处决定（P9）；`hooks.py` 只收集事实、照做、写说明。

## 3 Claude Code 的 hooks

不改 Claude Code，只加配置（`python -m rightofway.code install` 写进项目的 `.claude/settings.local.json`）。每次事件运行 `python -m rightofway.code hook`，从标准输入读 JSON，输出 JSON。每次都是一个新进程，所以每次都加锁（几个 hook 可能同时运行）、读账本、做完存回去。

| 事件 | 做什么 |
|---|---|
| SessionStart | 告诉 Agent 规则，以及现在哪些行受保护 |
| UserPromptSubmit | 人在消息里写"交还 ……"就交还（第 4 节）；告诉 Agent 它上次看之后别人改了什么（R22） |
| PreToolUse：Edit、MultiEdit、Write、NotebookEdit | 算出这次编辑之后文件的样子；碰到不能动的行，**整次拒绝**（一行都不写），告诉它是哪几行、现在是什么内容、怎么请人交还 |
| PreToolUse：Bash | 命令会改什么事先不知道，只记下"开始了" |
| PostToolUse、PostToolUseFailure | 按磁盘上的实际内容结算（3.2–3.4）；读文件（Read）之后，告诉它这个文件里它没看过的变化 |

### 3.1 编辑之前：整次拒绝

Edit 按 `old_string`、`new_string`、`replace_all` 算（和 Claude Code 一样是字符串替换；文件是 CRLF、编辑里写的是 LF 时换成 CRLF 再找），MultiEdit 依次算，Write 就是 `content`。算出来的新内容和账本里的比，碰到不能动的行就拒绝（`permissionDecision: "deny"`，理由给模型看）。拒绝时不做任何部分：不会出现只生效一半的代码（例如改名只改了一半）。

同一处被拒到第 3 次时，提醒人（`systemMessage`）："AI 已经 3 次想改你改过的……，如果你同意它改，在对话里输入：交还 ……"。

算不出结果的（`old_string` 找不到，工具多半会自己报错）先放行，事后核对（3.2）。NotebookEdit 算不出结果：文件里有对它受保护的部分，就整次拒绝。

### 3.2 编辑之后：按实际内容结算

- 磁盘上的内容和事先算的一样：都是这个 Agent 的。
- 不一样（执行期间人也存了盘，或者工具实际做的和算的不一样）：算出来的那部分是 Agent 的，多出来的部分说不准是谁的，记为来源不明、按人的修改保护。不改回去：多出来的可能正是人刚存的。
- 事先没能算出结果、实际又碰到了不能动的行：把这个文件改回编辑之前，Agent 的版本另存一份（账本目录的 `backups/`），告诉 Agent 和人。

### 3.3 命令之后：碰到人的行的文件整个改回

命令不是原子的，事先也不知道它会改什么。结束之后看磁盘上的变化：

- 文件的变化碰到了不能动的行：把**这个文件**整个改回命令执行前的样子（按文件整次拒绝），Agent 的版本另存一份。别的文件照常生效。所以一条命令可能只生效一半（例如跨文件改名：人的文件改回了，别的文件改了名），如实告诉 Agent，请它检查。
- 删掉了有受保护的行的文件：放回去。
- Agent 的命令里做的提交（`git commit`）不算人交还（第 4 节）。

### 3.4 命令执行得比较久：说不准是谁改的

命令执行期间人也可能存盘（例如测试跑了两分钟，人接着写代码）。这时"命令期间的变化都是 Agent 的"就可能把人的修改算成 Agent 的（P1），人的修改也不再受保护（P5）；把它改回去更糟：改掉的可能正是人刚打的字。所以分开：

- 变化之后的内容就是 git 里的样子（和 HEAD 或暂存区一样：checkout、reset、stash、pull……）：是命令做的，按 3.3 处理。
- 命令很快就结束了（不超过 3 秒，`RIGHTOFWAY_BASH_WINDOW` 可以改）：人插进来的可能很小，按 3.3 处理。
- 其余的（命令执行了比较久，内容又不是 git 里的）：说不准是谁的，记为来源不明、按人的修改保护；不改回去，碰到了人改过的行时，把改动之前的版本另存一份，提醒人："……说不准是你改的还是命令改的：现在的内容保留，如果不是你改的，可以用这个版本改回去。"
- 命令没等到结束通知（超时、被打断）：这期间的变化一律记为来源不明。

在后台运行的命令（`run_in_background`）结束通知来得早：之后它改的文件会被当成人改的（多保护，不会少保护）。

### 3.5 出错时不放行

hook 自己出错（例如账本坏了）时，Edit、Write、Bash 这些执行前的检查返回退出码 2，这次不执行，提示人检查（`python -m rightofway.code status`、`reset`）。配置里还加了 `"onFailure": "block"`：hook 起不来时也不放行（需要 Claude Code 2.1.295 以上）。宁可这次不执行，也不在保护失效时改文件（P1、P5）。

### 3.6 告诉 Agent 什么（P8）

都只从账本生成：

- 被拒时：哪几行、谁改的、现在的内容（带行号），"以现在的内容为准，只改别的部分"，怎么请人交还；按旧印象写的，先重新读。
- 读文件之后、人发消息时：它上次看之后别人改了什么（同一件事只说一次），哪些它不能改。
- 命令之后：哪些文件改回了、碰到了谁的哪几行、它的版本存在哪里、别的文件照常生效、可能只生效了一半。

## 4 交还、提交

- **人在对话里交还**：消息里写"交还 路径"（整个文件）、"交还 路径:起-止"（几行，行号从 1 开始）、"交还 全部"（也可以写 `rightofway release ...`）。只有命令的消息不发给 AI（hook 拦下，告诉人"已交还"）；命令加上别的话照常发给 AI，带上说明。AI 写的提示到不了这里：子 Agent（Task 工具）收到的提示里的"交还"不算。
- **命令行**：`python -m rightofway.code release 路径:起-止`、`status`（现在哪些受保护）。
- **人提交（commit）之后**，提交进去的行（和 HEAD 一样的行、已经提交的删除）不再保护，变成基线。没提交的照样保护。判断"是人提交的"：HEAD 在 Agent 的执行之外变了。Agent 的命令里做的提交不算（它不能替人交还，P2）。

## 5 局限

1. **没存盘的修改看不到**（2.2）。开自动保存。
2. **命令不是原子的**：3.4 的分法降低了把人的修改算错的机会，但快的命令期间人存的盘仍会被算成 Agent 的；命令只生效一半的情况只能告诉 Agent。
3. **按行**：语义上的冲突发现不了（例如人改了一个变量名，Agent 在别的行还用旧名字）；只保证人改的那几行不被改。
4. **改名、移动文件**：等于删掉旧文件、新建一个；人改过的旧文件会被放回去，新文件照常生效，可能出现两份。
5. **读了一部分**（Read 带 offset、limit）也算读过整个文件。
6. **防的是 Agent 的习惯和误操作，不是有意绕过**：Agent 可以用 Bash 改用户目录里的 Claude Code 配置、关掉 hooks。
7. **规模**：每次 hook 扫描一遍文件（先看修改时间和大小）；3000 个文件的仓库每次约 0.06–0.08 秒（不含 Python 启动）。账本存着变过的文件的内容；和 git 暂存区一样的文件不另存。
8. **还没验证**：真的 Claude Code（hook 的输入格式以官方文档为准，有几处文档里没写全：Write 的 `content`、MultiEdit 的 `edits`、NotebookEdit 的字段）；Windows 上的 Claude Code。

## 6 测试和实验

- `tests/test_code.py`（36 个）：按行的标记和删除点；Edit/Write 整次拒绝；整份重写、写回人删掉的；配置只有人能改；`git checkout`、格式化、找回人删掉的文件；交还（消息、只有命令、子 Agent 的提示不算）；人提交和 Agent 提交；切分支；告诉 Agent 它错过了什么；两个 Agent；反复被拒提醒人；结果和预计不一样；命令没等到结束通知；命令执行得比较久（人同时打字、git、删除、新生成的代码）；没有 git；不是 git 仓库、文件又太多时不猜；二进制文件；锁；安装；真的起进程跑 hook；没有 tool_use_id 也能对上；出错不放行。
- **实验 K**（`python -m experiments.exp_k_code`，也在 `run_all` 里）：Agent 先读了代码，人接着改了 shop.py 的三处（改价格系数、删掉一个函数、加一个函数），Agent 按旧印象做下一步。Agent 是写好的脚本，工具行为照 Claude Code；被拒之后照着说明重新读、只改别的部分。

| 写法 | 有 RightOfWay：人的修改被覆盖 | 没有保护：人的修改被覆盖 |
|---|---|---|
| 精确修改（改税率；再按计划改价格那一行） | 0 | 1 |
| 整份重写 | 0 | 3（删掉的函数也回来了） |
| 丢弃改动（git checkout） | 0 | 3 |
| 两个 AI（A 改税率，B 按旧内容整份重写） | 0（A 的修改也在） | 3，A 的修改也丢了 |
| 跨文件改名（命令，测量） | 0；shop.py 改回，report.py 改了名：只生效了一半，已告诉 Agent | 0 |

最后一行就是第 5 节第 2 条：命令只能事后核对。
